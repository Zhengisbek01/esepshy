# Esepshy

Единый расчётный центр ЖКХ с ИИ-сверкой начислений и дистанционным учётом электроэнергии, тепла, воды и газа.

Проект ТОО «JASA Ltd» (Алматы) для программы G-TON Astana Hub. Задачи акиматов: ЕРЦ, учёт воды, учёт электроэнергии.

## Состав репозитория

| Путь | Что это |
| --- | --- |
| `src/` | Платформа: React + Vite, 10 ролевых кабинетов, движок биллинга, ИИ-сверки, аномалий учёта, KPI и скоринга долгов |
| `public/prototype.html` | Первый прототип (один HTML-файл) |
| `vercel.json` | Настройки сборки для Vercel |
| `docs/roles.md` | Роли платформы и права доступа по модулям |
| `docs/user-scenarios.md` | Пользовательские сценарии по ролям (38 сценариев) |

## Запуск

```
npm install
npm run dev      # локально, http://localhost:5173
npm run build    # сборка в dist/
```

Тестовая версия работает без сервера: данные генерируются в браузере (мкр «Самал-2», 12 домов, 600 лицевых счетов, 12 месяцев) и сохраняются в localStorage. Кнопка «Сбросить демо» возвращает исходное состояние. Тарифы демонстрационные.

## Вход

- **Сотрудники** — логин и пароль организации. 5 неверных паролей подряд блокируют вход на 1 минуту. Для администратора — второй фактор: код по SMS (в тестовом режиме код показан на экране).
- **Жители** — через eGov (тестовый режим: вход по ИИН, подпись имитируется).
- Сессия завершается после 30 минут бездействия. Администратор выдаёт временные пароли; при первом входе их нужно сменить.
- Демо-доступы: пароль `Esepshy2026!` для всех учётных записей (логины на экране входа).
- Пароли хранятся только как хеш SHA-256. В промышленной версии вход переезжает на сервер.

## Структура кода

- `src/data/generate.js` — генератор демо-микрорайона
- `src/lib/engine.js` — биллинг, ИИ-сверка (6 типов ошибок), баланс «ввод — квартиры», аномалии, KPI, скоринг
- `src/store.jsx` — состояние, журнал действий, вход
- `src/pages/*` — кабинеты ролей

## Модули платформы

1. Единая квитанция и онлайн-оплата
2. ИИ-сверка начислений (6 типов ошибок)
3. Дистанционный учёт: баланс «ввод в дом — сумма квартир», аномалии
4. Модель задолженности и сегменты риска
5. Панель KPI для акимата

## KPI пилота (из задач акимата)

| Показатель | Цель |
| --- | --- |
| Платежи онлайн | ≥ 70% |
| Ошибки в начислениях | ≤ 5 на 1 000 счетов |
| Умные счётчики воды и электроэнергии | 80% |
| Умные теплосчётчики | 70% |
| Потери воды | −15% |
| Потери электроэнергии | −10% |
